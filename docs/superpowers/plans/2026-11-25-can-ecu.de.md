# Implementierungsplan für CAN-Steuergeräte

> **Für agentische Bearbeiter:** superpowers:executing-plans direkt in dieser Sitzung verwenden. Der Benutzer hat die fortlaufende Implementierung autorisiert.

**Ziel:** tatsächliche CAN-Steuergeräte auslesen, ohne Antworten verschiedener ECUs zusammenzuführen.
**Architektur:** strikter Decoder für gerahmte Antworten zusammen mit vorhandenen Nutzdatendecodern, ausdrückliche Auswahl im Treiber und optional gespeicherter Geltungsbereich.
**Technologien:** vorhandene TypeScript-/ELM327-Transporte; keine Abhängigkeit.
**Spezifikation:** `docs/superpowers/specs/2026-11-25-can-ecu-design.md`.

## Vorgaben und Prüfschwerpunkte
- Keine standardmäßig geratene Motorsteuergeräteadresse; tatsächlich erkannte IDs auswählen.
- Keine Vermischung von Rahmendaten, keine Akzeptanz von Lücken und keine Behandlung von NO DATA als null.
- Ein ECU-Wechsel oder eine fehlgeschlagene Adapterkonfiguration entzieht die Löschfreigabe.
- Alte Snapshots/Sicherungen bleiben lesbar. Neue Snapshots behalten den ECU-Geltungsbereich in Exporten/Berichten.
- Auswahlanfragen der Oberfläche müssen die Verbindung erhalten; Fehler bleiben ausdrücklich sichtbar.

## Aufgabe 1: Rahmen und Treiber
- [x] RED/GREEN-Tests für 11-/29-Bit-IDs, verschachtelte ISO-TP-Übertragung, abgeschnittene Daten/Sequenzen/Padding, Auswahl und physisch adressierte Anfragen, Antworten falscher Steuergeräte sowie Löschschutz. Die Validierung der CAN-DTC-Anzahl hat eine eigene RED/GREEN-Regression.
- [x] `mobile/src/obd/can.ts`: CanProtocol, CanEcu, Protokoll-/Nachrichtenparser, physische Anfrage-IDs, Fehler bei erforderlicher Auswahl.
- [x] Treiber und Snapshot-Validator aktualisieren; die ältere Test-Fixture ergänzt eine echte ATDPN-Antwort.

## Aufgabe 2: Anwendungsintegration
- [x] Echte ECU-Auswahl in der Oberfläche und Anzeige des Geltungsbereichs hinzufügen; die Verbindung bei erforderlicher Auswahl erhalten.
- [x] Geltungsbereich in Berichten/Sicherungen; validierten Geltungsbereich durch die KI-Whitelist von Client/Server und den Zustimmungsdialog führen. Vier Integrationsregressionen mit beobachtetem RED → GREEN.
- [x] 128 Tests bestanden, TypeScript/Lint mit Exit-Code 0, Web-/iOS-/Android-JS-/Hermes-Exporte mit Exit-Code 0. Ein unabhängiger Prüfer führte 36 gezielte Tests aus und prüfte die primäre ELM-Dokumentation; keine handlungsrelevanten Befunde. Verhalten auf physischen Geräten/ECUs und native Binärdateien bleiben ungeprüft.
