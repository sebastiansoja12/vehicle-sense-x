# Dopracowanie interfejsu

Cel: spójny, czytelny interfejs na telefonie i komputerze. Zachować jasny charakter aplikacji, czerwony akcent, rzeczywiste dane i wszystkie istniejące działania. Użytkownik zlecił pracę bez pytań oraz publikowanie na main.

Podejście: poprawić istniejące wspólne komponenty zamiast dodawać bibliotekę UI lub osobną aplikację web. Dodać boczną nawigację tylko w szerokim web, z tą samą granicą ukrywania dolnych zakładek. W telefonie zachować zakładki i bezpieczne odstępy systemowe. Start: profil auta, szybkie akcje, miesięczne podsumowanie, diagnostyka, terminy i moduły dodatkowe. Nie generować zdjęć udających samochód właściciela ani danych demonstracyjnych.

Pliki: model nawigacji i jego test; wspólna powłoka; motyw i komponenty; profil samochodu i wydzielony Start; układy Routera; karty akcesoriów. Najpierw testy aktywnej trasy i granicy układu, potem implementacja. Sprawdzić telefon, wąski ekran, komputer, formularz, puste stany i filtry; następnie typy, lint, suite, dokumentację i eksporty. Dane garażu i logika finansowa/OBD pozostają poza zakresem zmian.

## Weryfikacja interfejsu

Sprawdzono Start, Garaż, formularz tankowania, pusty garaż i dodawanie samochodu, filtry/karty akcesoriów oraz zmianę układu przy 320, 390, 1280 i 1440 px. Nie zapisywano nowych danych do garażu. Poprawiono nakładanie sekcji po przełączeniu kolumn, układ statystyk 2 × 2 oraz krótkie etykiety na najwęższym ekranie. Boczne menu obejmuje także nowe ekrany garażu. Typy, lint i eksporty JS web/iOS/Android przechodzą; pełna suite bieżącego katalogu: 371 testów zaliczonych. Końcowy commit obejmuje UI i jego testy, bez przejmowania równoległych, niezatwierdzonych funkcji. Fizyczny telefon i zmienione systemowe skalowanie tekstu pozostają do sprawdzenia na urządzeniu.

Wydzielona kopia zmian UI przeznaczona do publikacji przeszła osobno 360 testów, kontrolę typów, lint, kontrolę dokumentacji i eksporty JS.
