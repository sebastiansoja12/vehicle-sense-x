# OBD-Verbindung und Bluetooth-Radio — Implementierungsplan

> Für die Ausführung: superpowers:executing-plans für die Arbeit in dieser Sitzung verwenden.

**Entwurf:** [Entwurf](../specs/2026-11-26-obd-radio.de.md)

**Ziel und Architektur:** Ziel: echte ELM327-Messungen über BLE, Android SPP und WLAN; das Radio dient als Audioausgabe des Telefons. Ein gewöhnliches A2DP/HFP-Radio ist kein Diagnoseadapter.

**Technologie:** Expo 58, React Native 0.88, TypeScript, Node 24, ELM327, expo-speech.

## Gemeinsame Grenzen

Annahme: Das Telefon überträgt Ton an das Radio. Die Frage zu Android-Autoradios bleibt offen. Ohne physische Hardware bestätigen Tests weder alle Adapter noch gleichzeitige Bluetooth-Profile.

## Prüfschwerpunkte

BLE-Startmeldungen vor dem ersten Befehl auf 8192 ASCII-Zeichen begrenzen. Eine Trennung macht die Sitzung ungültig. Nach Live Data erfordert das Löschen einen neuen vollständigen Bericht.

## Aufgaben

- [x] Den Startmeldungsfehler in `mobile/tests/obd-ble.test.mjs` reproduzieren, die Meldung in `ble-session.ts` begrenzen und Tests ausführen.
- [x] `Elm327Driver.readLiveParameters()` für neue Messwerte, nicht unterstützte PIDs, ECU-Wechsel und ungültige Sicherungen testen. Separate Abfragen und einen automatischen Scan in `DiagnosticsScreen.tsx` ergänzen.
- [x] System-Kopplung und einen ausdrücklichen Audiotest mit Stopp beim Verlassen des Bildschirms ergänzen; native Fehler und Ablehnung im Browser prüfen.
- [x] Alle Tests, Typprüfung, Lint, Dokumentationsprüfung und Exporte ausführen; Code prüfen, Commits erstellen und Änderungen hochladen.
- [ ] Ein signiertes Android-APK bauen, das Artefakt prüfen und Grenzen der Hardwareprüfung dokumentieren.
