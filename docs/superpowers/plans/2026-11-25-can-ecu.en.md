# CAN ECU Implementation Plan

> **For agentic workers:** use superpowers:executing-plans inline. User authorized continuous implementation.

**Goal:** read actual CAN controllers without merging different ECU replies.
**Architecture:** strict framed reply decoder plus existing payload decoders, explicit driver selection and persisted optional scope.
**Tech Stack:** existing TypeScript/ELM327 transports; no dependency.
**Spec:** `docs/superpowers/specs/2026-11-25-can-ecu-design.md`.

## Constraints and review focus
- No default guessed engine address; choose actual discovered IDs.
- No mixing frame data, accepting gaps or treating NO DATA as zero.
- Changing ECU or failed adapter configuration invalidates clearing.
- Old snapshots/backups remain readable. New snapshots keep ECU scope in exports/reports.
- UI selection requests must preserve the connection; errors still fail visibly.
