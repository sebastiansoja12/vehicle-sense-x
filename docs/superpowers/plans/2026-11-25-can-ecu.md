# Plan implementacji obsługi sterowników CAN ECU

> **Dla agentów wykonawczych:** użyj superpowers:executing-plans w bieżącej sesji. Użytkownik autoryzował ciągłą implementację.

**Cel:** odczytywać rzeczywiste sterowniki CAN bez łączenia odpowiedzi różnych ECU.
**Architektura:** rygorystyczny dekoder odpowiedzi ramkowanych, istniejące dekodery ładunków, jawny wybór w sterowniku i zapisywany opcjonalny zakres.
**Stos technologiczny:** istniejące transporty TypeScript/ELM327; bez nowych zależności.
**Specyfikacja:** `docs/superpowers/specs/2026-11-25-can-ecu-design.md`.

## Ograniczenia i obszary przeglądu
- Bez zgadywanego domyślnego adresu silnika; wybierać rzeczywiście wykryte identyfikatory.
- Nie mieszać danych ramek, nie akceptować luk ani nie traktować NO DATA jak zera.
- Zmiana ECU lub nieudana konfiguracja adaptera unieważnia możliwość kasowania.
- Stare odczyty/kopie pozostają czytelne. Nowe odczyty zachowują zakres ECU w eksportach/raportach.
- Żądania wyboru w interfejsie muszą zachować połączenie; błędy nadal są widoczne.
