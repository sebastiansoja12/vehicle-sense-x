# OBD and Bluetooth radio — 0.4.0

Source 0.4.0/build 6 retains data schema 3. Connecting starts a full ECU scan; an adapter acknowledgement alone is insufficient. With multiple CAN controllers, the user selects an actually discovered address. Live Data polls supported measurements and voltage every 5 seconds, after the preceding operation finishes. The report retains its own timestamp and codes. Clearing after Live Data requires a new full scan.

BLE tolerates up to 8192 ASCII startup characters before the first command. BLE, Android SPP and TCP report connection loss between commands too. The UI stops polling and requires reconnection. No measurement generator or example vehicle was added.

## Radio and audio

The Connections screen is accessible from settings without a vehicle and from diagnostics. Android opens Bluetooth settings; iOS provides manual steps and opens app settings. The user pairs devices and selects output in the OS. The radio serves as phone audio output; ordinary A2DP/HFP does not expose ECU data. Running the app directly on an Android head unit requires separate validation.

The test plays a fixed phrase through OS speech synthesis. It sends no VIN or diagnostics to the speech engine and does not claim a confirmed radio connection. Stop, leaving the screen, backgrounding and a 20-second deadline cancel playback, including during Android TTS initialization. A voice may need installation in the OS. Hardware actions are disabled in the browser.

## Verification

Complete local suite: 213/213 tests, including real TCP/HTTP sockets. Types and lint pass using Node 24.18.0. Tests cover startup banners, disconnections, automatic scans, Live Data, CAN scope, clear guards and speech cancellation.

Review found delayed Android TTS playback after cancellation during initialization. A test reproduced the failure; the fix waits for engine readiness and checks cancellation before scheduling speech. The TCP test waits for server-side connection acceptance to remove a race in the test itself.

Browser checks covered the settings entry, Connections route, disabled hardware actions and navigation to diagnostics without a vehicle. The user garage was not changed. A native Android APK and iOS simulator package for 0.4.0 remain to be built; 0.3.0 packages do not include these changes. No store submission was performed.

## Hardware procedure

Install the APK, plug the adapter into a parked vehicle and switch on the ignition. BLE: scan for the device and enter vendor UUIDs if needed. Android SPP: pair in the OS, then select the bonded adapter. Wi-Fi: join its network and enter the documented address and port. Press “Połącz i odczytaj samochód”. Check ECU scope and report timestamp, then Live Data and adapter loss. Test clearing on a suitable bench while retaining a report backup.

Pair the radio, select Bluetooth Audio, play the test and confirm sound from the car speakers. Check concurrent OBD reading, stopping, backgrounding and adapter loss. Disable silent mode on iPhone. No physical phone, adapter or radio is connected; tests and builds do not confirm compatibility with every device. The lack of an active Apple Developer account still prevents a store IPA.
